# 去重系统测试用例

本文档描述去重系统的手动测试用例，涵盖精确匹配、模糊匹配和版本管理功能。

## 测试环境准备

1. 确保数据库已迁移到最新版本
2. 准备测试邮箱数据（包含各种重复场景）
3. 启动应用程序

## 测试场景

### 场景 1: 精确匹配（版本关系）

**描述**: 同一学生针对同一作业的多次提交

**测试步骤**:
1. 学生 S001（张三）首次提交"作业1"
2. 同一学生再次提交"作业1"
3. 查看提交记录列表

**预期结果**:
- 第二次提交显示为第一次提交的子记录
- 关系类型为 `VERSION`
- 第一次提交的 `is_primary=True`
- 第二次提交的 `parent_id` 指向第一次提交
- UI中第二次提交缩进显示在第一次提交下方
- 可以折叠/展开查看版本历史

**验证点**:
- [ ] 主记录正确识别
- [ ] 版本关系正确建立
- [ ] UI正确显示层级关系
- [ ] 折叠/展开功能正常

---

### 场景 2: 学号相同（可能重复）

**描述**: 学号相同但姓名不同的提交（可能是姓名错误）

**测试步骤**:
1. 学生 S001（张三）提交"作业1"
2. 学号 S001 但姓名为"李四"提交"作业1"
3. 查看提交记录列表

**预期结果**:
- 两个提交都显示为主记录
- 第二个提交标记为 `POSSIBLE_DUP` 关系
- 第一个提交的 `related_submissions` 包含第二个提交
- 关系类型为 `POSSIBLE_DUP`
- 系统提示"学号相同但姓名不同，可能是重复"

**验证点**:
- [ ] 两个记录都可见（非版本关系）
- [ ] 可能重复标记正确显示
- [ ] 用户可确认是否为真实重复
- [ ] 可以合并或确认为独立提交

### 场景 5: 混合场景

**描述**: 版本关系和可能重复的混合情况

**测试步骤**:
1. 学生 S001（张三）提交"作业1" → 记录A（主记录）
2. 学生 S001（张三）再次提交"作业1" → 记录B（A的版本）
3. 学号 S001 但姓名为"张三丰"提交"作业1" → 记录C（A的可能重复）
4. 学生 S002（李四）提交"作业1" → 记录D（独立记录）
5. 查看提交记录列表

**预期结果**:
- 记录A: 主记录，子记录包含B和C
- 记录B: A的版本，缩进显示
- 记录C: A的可能重复，缩进显示
- 记录D: 独立主记录
- UI正确显示层级关系
- 折叠/展开功能正常

**验证点**:
- [ ] 多个子记录正确显示
- [ ] 不同关系类型正确区分
- [ ] UI层级关系清晰
- [ ] 折叠/展开所有子记录
- [ ] 可能重复和版本关系都正确

### 场景 7: 姓名相似度测试

**描述**: 测试姓名相似度阈值

**测试步骤**:
1. 学生 S001（张三）提交"作业1"
2. 使用以下姓名分别提交"作业1":
   - "张小三"（相似）
   - "张三丰"（相似）
   - "张三的"（相似）
   - "李张三"（部分相似）
   - "王小五"（不相似）
3. 查看每个提交的关系建立情况

**预期结果**:
- "张小三": 建立可能重复关系（相似度 > 0.6）
- "张三丰": 建立可能重复关系（相似度 > 0.6）
- "张三的": 建立可能重复关系（相似度 > 0.6）
- "李张三": 可能建立关系（取决于相似度）
- "王小五": 不建立关系（相似度 < 0.6）

**验证点**:
- [ ] 相似度计算正确
- [ ] 阈值过滤正常工作
- [ ] 边界情况处理正确

## 测试数据清理

测试完成后，清理测试数据：

```sql
-- 删除测试提交记录
DELETE FROM submissions WHERE assignment_name LIKE '测试%';
DELETE FROM submissions WHERE student_id LIKE 'S%';

-- 重置自增ID
DELETE FROM sqlite_sequence WHERE name='submissions';
```

## 自动化测试

除了手动测试，还可以运行自动化测试：

```bash
# 运行所有单元测试
pytest tests/unit/ -v

# 运行特定测试
pytest tests/unit/test_fuzzy_matcher.py -v
pytest tests/unit/test_submission_group_manager.py -v

# 运行集成测试
pytest tests/integration/ -v
```
