# 多作业提交重新检测脚本

## 概述

此目录包含用于重新检测和处理多作业提交的脚本。

## 背景

系统已经实现了多作业提交的检测和处理功能，包括：
- ✅ 前端UI颜色标记（紫色边框、浅紫色背景、📎指示器）
- ✅ 多作业检测器（AI驱动）
- ✅ 多作业处理器（自动分组）

但是历史数据中大部分记录没有运行过多作业检测，因此 `group_id` 字段为空。

## 脚本说明

### 1. quick_detect_multi_assignment.py - 快速检测脚本

**用途**: 快速分析数据库中的多作业提交情况，不进行任何修改。

**使用方法**:
```bash
python scripts/quick_detect_multi_assignment.py
```

**输出内容**:
- 基本统计（总记录数、有/无 group_id 的记录数）
- 提交组统计（总数、状态分布）
- 组大小分布
- 最大的提交组
- 检测方法分布
- 可能需要重新处理的记录（多附件但没有 group_id）
- 建议

**示例输出**:
```
============================================================
多作业提交快速检测
============================================================

【基本统计】
总提交记录数:           233
已有 group_id 的记录:   66 (28.3%)
没有 group_id 的记录:   167 (71.7%)

【提交组统计】
总提交组数:             33
  - 已完成:             32
  - 处理中:             0
  - 失败:               1
  - 待人工审核:         0

【建议】
[OK] 有 167 条记录没有 group_id
  建议运行: python scripts/redetect_multi_assignment.py
[OK] 其中有 25 条有多附件，很可能是多作业提交
  优先处理这些记录可获得更好的效果
```

### 2. redetect_multi_assignment.py - 重新检测脚本

**用途**: 重新运行多作业检测并更新数据库记录。

**使用方法**:
```bash
# 正常模式：只检测没有 group_id 的记录
python scripts/redetect_multi_assignment.py

# 强制模式：重新检测所有记录（包括已有 group_id 的）
python scripts/redetect_multi_assignment.py --force

# 测试模式：只检测不更新数据库
python scripts/redetect_multi_assignment.py --dry-run

# 限制处理数量（用于测试）
python scripts/redetect_multi_assignment.py --limit 10

# 组合使用
python scripts/redetect_multi_assignment.py --dry-run --limit 5
```

**命令行参数**:
- `--force`: 强制重新检测所有记录（包括已有 group_id 的）
- `--dry-run`: 只检测不更新数据库，用于测试
- `--limit N`: 限制处理的记录数量（用于测试）

**处理流程**:
1. 获取需要处理的记录（根据参数决定范围）
2. 连接到 IMAP 服务器
3. 对每条记录：
   - 从 IMAP 获取邮件数据
   - 运行多作业检测
   - 如果检测到多作业，创建/更新提交组
   - 如果是单作业，保持原样
4. 生成统计报告

**统计报告示例**:
```
============================================================
检测完成 - 统计报告
============================================================
总处理记录数:     50
检测为多作业:     12
检测为单作业:     35
检测失败:         2
已处理(跳过):     1
处理错误:         0
============================================================
```

## 推荐使用流程

### 第一步：运行快速检测

先运行快速检测脚本了解当前状态：
```bash
python scripts/quick_detect_multi_assignment.py
```

### 第二步：测试模式运行

使用测试模式验证检测逻辑是否正常：
```bash
# 先处理少量记录
python scripts/redetect_multi_assignment.py --dry-run --limit 5
```

### 第三步：实际处理

确认无误后，开始实际处理：
```bash
# 正常模式：只处理没有 group_id 的记录
python scripts/redetect_multi_assignment.py
```

### 第四步：验证结果

再次运行快速检测，查看改进效果：
```bash
python scripts/quick_detect_multi_assignment.py
```

### 第五步：刷新UI

重新打开应用或点击刷新按钮，查看前端UI中的颜色标记。

## 注意事项

1. **网络连接**: 重新检测脚本需要连接到 IMAP 服务器，请确保网络连接正常。

2. **API费用**: 多作业检测使用AI，会产生API费用。建议先用 `--limit` 参数测试少量记录。

3. **处理时间**: 处理大量记录可能需要较长时间，建议分批处理。

4. **数据安全**: 脚本不会删除任何数据，只会添加/更新 `group_id` 和 `group_order` 字段。

5. **中断恢复**: 如果处理过程中中断，可以重新运行脚本。已处理的记录会被跳过（除非使用 `--force`）。

## 故障排查

### 问题：IMAP 连接失败
```
无法连接到 IMAP 服务器
```
**解决方案**:
- 检查网络连接
- 检查配置文件中的 IMAP 设置
- 确认邮箱服务正常

### 问题：检测失败率较高
```
检测失败:         15
```
**解决方案**:
- 检查 AI API 配置是否正确
- 查看日志了解具体失败原因
- 可能需要调整检测参数

### 问题：中文乱码
```
锟斤拷锟斤拷
```
**解决方案**:
- 这是 Windows 控制台编码问题，不影响功能
- 可以在 PowerShell 中运行：`chcp 65001` 切换到 UTF-8
- 或者将输出重定向到文件：`python script.py > output.txt`
