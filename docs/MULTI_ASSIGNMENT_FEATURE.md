# 多作业提交功能说明

## 概述

多作业提交功能允许学生在单封邮件中提交多个不同的作业，系统会自动识别并将每个附件分配到对应的作业。该功能通过AI智能分析邮件主题、附件文件名和邮件正文，确保每个附件都被正确归类。

### 主要优势

- **提升效率**：学生无需为每个作业单独发送邮件
- **降低出错率**：自动识别减少人工分类错误
- **灵活配置**：支持多种识别策略和严格程度设置
- **安全可靠**：严格模式确保所有附件都有明确归属

## 工作原理

### 检测优先级

系统按以下优先级检测多作业提交：

1. **邮件主题分析**（最高优先级）
   - 检查主题是否包含多个作业名称
   - 示例：`作业1+作业2提交 - 张三`、`实验报告1和2 - 李四`

2. **附件文件名分析**（中等优先级）
   - 分析附件名称中的作业标识
   - 示例：`作业1_实验报告.pdf`、`作业2_代码.zip`

3. **邮件正文分析**（最低优先级）
   - 从正文内容中提取作业信息
   - 示例：`附件是我的作业1和作业2`

### 处理流程

```
收到邮件
    ↓
启用多作业检测？
    ├─ 否 → 按单作业处理
    └─ 是 → 继续
         ↓
    检查缓存
         ↓
    AI多作业识别
         ↓
    识别结果完整？
         ├─ 否 → 标记为人工审核
         └─ 是 → 创建提交组
              ↓
         处理每个作业
              ├─ 存储附件
              ├─ 创建数据库记录
              └─ 更新组状态
              ↓
         发送确认邮件
```

### 结果状态

- **completed（完成）**：所有作业处理成功
- **partial（部分完成）**：部分作业处理成功
- **failed（失败）**：所有作业处理失败
- **manual_review（人工审核）**：AI识别不完整，需要人工介入

## 配置说明

在 `.env` 文件中添加以下配置：

```bash
# ========== 多作业提交配置 ==========

# 启用多作业提交功能（默认: true）
ENABLE_MULTI_ASSIGNMENT=true

# 启用邮件主题检测（默认: true）
ENABLE_SUBJECT_DETECTION=true

# 启用附件文件名检测（默认: true）
ENABLE_FILENAME_DETECTION=true

# 启用邮件正文检测（默认: true）
ENABLE_BODY_DETECTION=true

# AI识别置信度阈值，范围0-1（默认: 0.7）
# 置信度低于此值时，结果会被标记为不完整
MIN_CONFIDENCE_THRESHOLD=0.7

# 严格模式（默认: true）
# 开启后，无法确定归属的附件会导致整个提交进入人工审核
# 关闭后，未归属的附件会被忽略，其他作业正常处理
STRICT_MODE=true

# 单个邮件最多附件数（默认: 10）
MAX_ATTACHMENTS_PER_GROUP=10

# 单个邮件最多作业数（默认: 5）
MAX_ASSIGNMENTS_PER_GROUP=5
```

### 配置详解

#### ENABLE_MULTI_ASSIGNMENT
总开关，控制整个多作业功能的启用状态。关闭后，所有邮件都按单作业处理。

#### MIN_CONFIDENCE_THRESHOLD
AI识别的置信度阈值，范围0-1。建议设置：
- `0.9`：非常严格，几乎不识别不明确的提交
- `0.7`：推荐值，平衡准确率和召回率
- `0.5`：宽松，可能产生误识别

#### STRICT_MODE
- **开启（推荐）**：确保所有附件都有明确归属，安全但可能需要更多人工审核
- **关闭**：忽略无法归属的附件，处理其他明确的作业，提高自动化率但可能遗漏附件

## 使用指南

### 学生提交指南

#### 推荐方式1：在邮件主题中明确说明

```
主题：作业1+作业2+作业3提交 - 2021001张三
附件：
  - 作业1_实验报告.pdf
  - 作业2_代码.zip
  - 作业3_数据分析.xlsx
```

#### 推荐方式2：使用明确的附件命名

```
主题：实验报告提交 - 2021001张三
附件：
  - 作业1_温度实验.pdf
  - 作业2_压力实验.pdf
  - 作业3_光学实验.pdf
```

#### 推荐方式3：在邮件正文中说明

```
主题：作业提交 - 2021001张三

正文：
助教好，

附件中包含以下作业：
1. 作业1的实验报告
2. 作业2的代码文件
3. 作业3的数据分析

请查收，谢谢！
```

### 最佳实践

1. **清晰的命名**：附件文件名包含作业名称，如 `作业1_报告.pdf`
2. **明确的主题**：邮件主题列出所有作业名称
3. **合理的数量**：单次提交不超过5个作业
4. **统一的格式**：使用标准的作业名称（作业1、作业2等）

### 常见错误示例

❌ **不推荐的提交方式：**
```
主题：作业
附件：
  - 报告1.pdf
  - 代码.zip
  - 数据.xlsx
```
这种命名方式不包含作业信息，AI难以识别。

❌ **过度复杂的提交：**
```
主题：所有作业都在这里了
附件：[20个文件]
```
附件过多会增加识别错误率。

## 管理员操作指南

### 查看多作业提交

在GUI界面中，多作业提交会有特殊标识：

1. **提交组标识**：在数据表中显示为 📊 图标
2. **提交详情**：点击可查看包含的所有作业
3. **处理状态**：显示当前处理状态（完成/部分/失败/待审核）

### 处理人工审核

对于标记为 `manual_review` 的提交：

1. 在GUI中找到该记录
2. 点击查看详细信息
3. 检查AI的识别结果和未归属附件
4. 手动分配附件到对应作业
5. 更新处理状态

### 导出数据

多作业提交会按以下方式导出到Excel：
- 每个作业单独一行
- 共享相同的 `group_id`
- 标注 `group_order` 显示顺序

## 故障排查

### 问题1：多作业未被识别

**可能原因：**
- AI置信度低于阈值
- 邮件主题/附件名/正文不包含明确的作业信息

**解决方案：**
1. 检查 `MIN_CONFIDENCE_THRESHOLD` 是否过高
2. 查看日志中的AI识别结果和置信度
3. 引导学生使用更明确的命名方式

### 问题2：附件归属错误

**可能原因：**
- AI识别错误
- 附件命名存在歧义

**解决方案：**
1. 检查 `STRICT_MODE` 是否开启
2. 查看日志中的识别过程和推理结果
3. 必要时降低 `MIN_CONFIDENCE_THRESHOLD` 或关闭 `STRICT_MODE`
4. 手动纠正错误的归属

### 问题3：所有附件都进入人工审核

**可能原因：**
- `STRICT_MODE` 开启且存在无法归属的附件
- AI识别完全失败

**解决方案：**
1. 检查邮件内容是否包含作业信息
2. 查看日志中的AI错误信息
3. 临时关闭 `STRICT_MODE` 以处理明确的作业
4. 引导学生重新提交

### 问题4：确认邮件发送失败

**可能原因：**
- SMTP配置问题
- 收件人地址错误

**解决方案：**
1. 检查 `ENABLE_REPLY` 是否开启
2. 验证SMTP连接状态
3. 查看日志中的邮件发送错误
4. 手动发送确认邮件

### 问题5：重复处理同一邮件

**可能原因：**
- 邮件未正确标记为已处理
- 数据库中缺少幂等性检查

**解决方案：**
1. 系统已内置幂等性检查，不应发生重复处理
2. 如果发现重复，检查 `submission_groups` 表中的 `email_uid`
3. 清理重复的组记录

## 性能优化

### 缓存机制

系统使用MD5哈希缓存识别结果：
- 缓存键：`主题:发件人:附件信息`
- 缓存存储：`multi_assignment_cache` 表
- 自动命中：相同邮件不会重复调用AI

### 批量处理建议

1. 合理设置 `MAX_ATTACHMENTS_PER_GROUP` 避免处理超时
2. 调整 `MIN_CONFIDENCE_THRESHOLD` 平衡准确率和速度
3. 定期清理缓存表以提升查询性能

## 技术细节

### 数据库架构

多作业提交使用以下表结构：

- `submission_groups`：提交组主表
  - 存储邮件级别的信息
  - 记录处理状态和AI置信度
  - 支持幂等性检查

- `submissions`：提交记录表
  - 每个作业一条记录
  - 通过 `group_id` 关联到提交组
  - `group_order` 标识顺序

- `attachments`：附件表
  - 记录每个附件的归属
  - 支持追溯附件来源

- `multi_assignment_cache`：缓存表
  - 存储AI识别结果
  - 避免重复调用API

### AI提示词

系统使用结构化的AI提示词确保识别质量：

- 系统提示：定义识别规则和输出格式
- 用户提示：包含邮件上下文信息
- 输出格式：JSON格式，包含置信度和推理过程

### 错误处理

系统实现了完整的错误处理机制：

1. **幂等性保证**：同一邮件不会重复处理
2. **事务回滚**：处理失败时清理已创建的文件和记录
3. **状态追踪**：详细记录每个阶段的处理状态
4. **错误日志**：完整的错误堆栈和上下文信息
